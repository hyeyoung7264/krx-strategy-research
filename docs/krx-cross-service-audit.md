# KRX 서비스 대조와 검토 목록

일봉·종목기본정보·지수의 선택한 원본을 함께 대조하고, 가격 감사에서 발견한 변화와 묶어 검토할 수 있다. 두 명령 모두 로컬 파일만 읽는다. API 호출, 원본 revision 자동 선택, 전략 실행 또는 시점 인증을 하지 않는다.

## 원본 대조

`config/krx-reference-audit.example.json`을 복사하여 실제 선택 원본의 경로, 날짜, 시장, 필요한 지수 이름을 명시한다.

```powershell
dotnet run --project src/Investment.Cli --no-restore -- krx-reference-audit --plan data/private/reference-audit-plan.json
```

`Sources`는 `Service`(`DAILY`, `BASIC`, `INDEX`), `Market`, `Date`, `SnapshotFile`의 목록이다. 같은 서비스·시장·날짜에는 하나의 원본만 허용한다. `ExpectedDates`는 정렬된 과거 날짜 목록이며 달력 인증을 뜻하지 않는다. `RequiredIndices`에는 시장별로 정확한 지수 이름을 하나 이상 지정한다. 예시는 `코스피`와 `코스닥`을 사용한다.

검사는 다음 근거를 보존한다.

- 공식 endpoint, 요청 시장·날짜, 관측시각, 원문 SHA-256과 재파싱한 행의 일치.
- 날짜별 가격·기본정보 종목 집합 및 상장주식 수의 일치. 누락값이나 0을 일치한 수량으로 인정하지 않는다.
- 기본정보의 시장·상장일, 중복 표준코드, 선택 날짜 사이 같은 종목코드의 표준코드 변화.
- 지정한 지수의 존재와 양수 종가. 지수 수익률이나 배당 재투자 성과를 검증하는 절차는 아니다.

계획에서 빠진 원본은 `MISSING_SNAPSHOT`, 선택한 빈 응답은 `EMPTY_RESPONSE`로 남긴다. 하나라도 누락·빈 응답이면 그 시장의 이전 식별자 비교를 끊는다. 선택한 파일을 읽을 수 없거나 원문이 변조됐다면 완성 보고서를 만들지 않고 실패한다. 누락일을 휴장일로 추정하지 않는다.

한 번에 한 날짜·시장의 세 원본과 이전 식별자 목록만 유지한다. 원본 파일은 100,000,000바이트, 정규화 행은 원본당 100,000개, 상세 발견 항목은 전체 100,000개로 제한한다. 초과 시 잘라서 성공시키지 않는다. 큰 자료는 명시적으로 구간을 나누고 구간 사이 비교에 필요한 경계 날짜도 선택해야 한다.

`InputHash`는 선택 원본의 출처·관측시각·원문 hash와 기대 날짜·시장·지수 조건에 연결된다. 로컬 파일 경로, 보고서 생성시각과 임의 ID는 제외한다. 해시를 다시 계산하려면 **원래 계획과 원본도 함께 보존**해야 한다. 이 해시는 공급원의 외부 서명이나 과거 공개시각 인증이 아니다.

기본정보 응답에는 `BAS_DD`가 없으므로 `Date`는 요청 날짜다. 같은 코드의 표준코드 변화는 두 관측 사이의 변화이며 정확한 변경일·상장 구간을 확정하지 않는다. 가격 자체의 OHLCV 형태와 큰 가격 변화는 기존 `krx-audit`로 별도 검사한다.

## 검토 목록

`config/krx-review-queue.example.json`의 `PriceAuditFiles`와 `ReferenceAuditFiles`에 각 감사 보고서를 명시한다. CLI가 저장한 `Report` wrapper와 보고서 단독 JSON을 모두 받는다.

```powershell
dotnet run --project src/Investment.Cli --no-restore -- krx-review-queue --plan data/private/review-queue-plan.json
```

종목 관련 발견 항목은 시장·종목코드별로 묶고, 종목을 지정하지 않은 문제는 시장·날짜별로 묶는다. 같은 날짜라는 이유로 다른 종목의 분할·합병을 연결하지 않는다. 원래 `Issues`, `Changes`, `IdentityChanges`의 모든 payload, 배열 위치, 보고서 식별자와 hash를 보존한다. 무거래 행 수 같은 일별 합계도 별도로 유지하며 종목별 정지 구간으로 바꾸지 않는다.

입력 JSON 텍스트 전체와 UTF-8 SHA-256을 저장하므로 wrapper의 실행 버전도 추적할 수 있다. CLI는 UTF-8 보고서를 받으며 손상된 인코딩을 조용히 치환하지 않고 거부한다. 선택적 UTF-8 BOM은 제거하므로 원래 파일 바이트 전체에 대한 해시라는 뜻은 아니다. 같은 보고서의 중복 선택은 거부한다. 서로 겹치는 서비스·시장·날짜의 원본 hash나 관측시각이 다르면 먼저 사용할 revision을 결정해야 한다.

전체 입력은 최대 1,000개 보고서·64 MiB의 UTF-8 텍스트, 발견 항목은 100,000개, 출처와 일별 합계의 합은 100,000개, 원본 연결은 1,000,000개로 제한한다. 원본 파일을 다시 읽거나 감사 보고서의 진실성을 독립 인증하지는 않는다. 검토 목록은 근거를 정리하는 결과이며 모든 묶음은 `OPEN`이다. 종목 식별은 `UNVERIFIED` 또는 `AMBIGUOUS`로 남기고 검토 완료나 dataset 인증으로 승격하지 않는다.

## 연구에 사용하기 전

문제가 발견되지 않아도 상태는 `STRUCTURAL_CHECKS_PASSED_UNREVIEWED`다. 당시 공개시각, 산업 분류, 체결 가능성, 완전한 기업행위·권리·정산 근거가 더 필요하다. 오늘 모은 과거 자료를 당시 관측한 paper 자료로 사용하지 않는다. 다음 단계는 검토 목록의 항목을 공식 원문과 대조하고, 지원되는 사건만 별도 시점 근거와 함께 데이터에 반영하는 것이다.
