# 검증 현황

최신 목표를 우선 반영하고 Owner가 선택한 일봉·수일 보유, OpenDART 공시/기업정보, KRX 공식 일봉 기준으로 구현했습니다. 실제 주문은 구현하지 않았습니다.

## 실행하여 확인한 항목

- .NET 10 솔루션과 C# 엔진 빌드.
- 모멘텀·평균회귀의 네 사전 등록 후보, 학습/검증/미래 테스트 분리, 5개 walk-forward fold와 마지막 holdout.
- 비용 전/후, 순청산가치, EV/MDD/Sharpe 등 지표, 위험·regime 중단과 통계 평가.
- 미래 값 변형, 다음날 공개 지연, 거래정지, gap 손실, 포지션 비중, 데이터 오류, 재현성, 버전/승격 gate 테스트.
- 실제 PostgreSQL 18 임시 독립 인스턴스에 OHLCV/실험 저장 및 조회, 원본 UPDATE/DELETE 거부.
- OpenDART 및 KRX의 공식 요청/응답 명세에 대한 mock HTTP·파싱·시점 보존 테스트.
- 기존 49개 자동 테스트가 Release에서 전체 통과(독립 PostgreSQL 연결 포함). 이후 전체 테스트 수와 최신 실행 결과는 아래 연구 확장 검증에 기록. 일반 실행은 PostgreSQL 연결 미설정 시 해당 테스트 하나를 명시적으로 skip.
- 빌드 소스 manifest와 실행 파일 SHA-256을 보존하고, 소스 변경 후 오래된 실행 파일 사용을 차단.
- 전체 연구 아카이브를 실제 CLI로 재현하여 모든 fold·holdout·평가가 일치함을 확인. 재현은 새 독립 증거로 세지 않음.
- 동시 증거 저장 시 완성 문서 하나만 게시, 직렬화 실패 시 깨진 증거 미게시, paper commit 후 사본 유실 시 거래 재실행 없는 복구 검증.
- 고정 seed 합성 연구를 실행했고 결과는 HOLD_OR_REJECT. 실패 결과, 원본 입력, 실행 소스와 해시, 지표 및 보고서를 보존.
- KRX 명시적 날짜 목록 수집, 요청 예산, 호출 간격, 중단 후 재개, 원본 보존, 빈 응답 검토 중단, 변조 검출, 동시 수집 거부와 오류 메시지 비노출을 mock 수집 테스트로 검증.
- 실제 CLI에서 키 미설정 시 HTTP 송신 없이 REQUEST_FAILED receipt를 보존함을 확인. 이 실행은 API 인증/실데이터 수집 검증이 아님.
- Paper 평가는 최신 확정 장부에 연결하고 관측별 재계산을 검사. 조작된 내보낸 사본/확정 잔고/인증 표시/감사 hash/후보 수, 과거 상태 선택, 실행 버전 변경, 실적을 넣은 시작 상태를 거부하는 테스트 통과. 장부 없는 직접 평가는 진단용으로 제한.
- Paper 시작은 완전한 연구 아카이브의 재현을 요구. 평가 판정/holdout 지표/walk-forward 통과 여부/데이터 분류 변경, 원본·소스 증거 누락을 거부하고 재현된 부적격 연구도 시작하지 않는 테스트 통과.

## 연구 확장 검증

- 최신 전체 Release 검증(2026-09-30): 239개 중 238개 통과, PostgreSQL 연결 미설정으로 1개 skip. 빌드 경고/오류 0. 기업행위 원문·해석 이력·과거 조회의 분리, 뒤늦게 확보한 근거의 보강, 소급 시간 변경 거절을 포함한다.
- 앞선 비용 진단 구현 버전에서는 비용 악화 진단 설정으로 합성 cohort-demo와 완전한 아카이브 재현을 실제 CLI에서 실행해 모든 결과가 일치했다. 5개 fold·최종 validation의 진단을 포함하며 판정은 HOLD_OR_REJECT다. 합성 자료의 계산 검증이며 실전 성과가 아니다.
- 단일 cohort에서 전략군별 선택 및 공유 자본 포트폴리오의 walk-forward/최종 검증/holdout을 평가. 기본 네 후보의 사전 검정 수는 개별 4 + 조합 4 = 8.
- holdout 가격 변경으로 학습 기반 선택과 결합 검증이 바뀌지 않음을 검증. 완전한 schema 2 아카이브에서 두 전략군·포트폴리오·통계 보정 수를 재현.
- 계산 분기 검증용으로 명시한 가공 데이터에서 실제 통과 연구가 단일 cohort 아카이브로 paper 시작까지 연결됨을 확인. 이 데이터는 실제 시장 연구나 forward 증거로 내보내지 않음.
- 데이터 revision·종목 집합·코드 변경으로 기존 holdout 거래일을 재사용하지 못하며, 겹치지 않는 새 기간과 동시 예약 충돌 처리를 검증.
- OpenAI 요청 schema·한도·키 비노출·거절/불완전/429 응답 처리, 학습만 보는 반복·실패 피드백·원본 응답 대조를 mock으로 검증. AI 가설 생성 시점 이전의 forward 기간은 승격 차단.
- OpenDART 연결 진단 12개 테스트 통과. 리디렉션 목적지를 분류만 하며 따라가지 않고, 키 반사·잘못된 회사·HTML·API 거절·응답 크기 초과·네트워크 오류는 인증 증거가 되지 않음. 실패 본문·URL·예외의 키를 기록하지 않음.

## 2026-09-27 실제 OpenDART 연결 시도

- Windows 사용자 환경의 OPENDART_API_KEY 설정을 확인. 값·hash·요청 URL을 출력하거나 공개 저장소에 넣지 않음. 보호된 사용자 환경을 읽는 실행에서 확인했으며 일반 sandbox의 미설정 결과와 구분.
- 공식 기업개황과 공시검색의 실제 읽기 전용 요청이 모두 HTTP 302를 반환. 목적지는 공식 `/error1.html` 오류 페이지이며 정상 API JSON·인증 성공·실데이터 수집은 미확인. 재빌드 후 같은 결과를 진단 receipt에 보존.
- Owner가 로그인한 브라우저 직접 제어를 요청해 Windows 접근성으로 인증키 관리 화면을 확인. 승인된 IP 등록 이력과 변경 신청의 담당자 승인 안내를 확인했으나, 이를 로컬 키의 API 인증 성공 증거로 세지 않음. 키 재발급·등록 IP 변경·신청 제출은 실행하지 않음.
- 실패 원인은 아직 확정되지 않음. 로컬 receipt는 `artifacts/`에 보존하며 사용자 계정·등록 IP·키·실제 요청 정보는 공개하지 않음.

## 2026-09-28 OpenDART 연구 확장

- 전체 재무제표(CFS/OFS·보고서 코드·통화·분기/누적 원문), 자기주식 취득 결정, 유상증자 결정의 공식 endpoint adapter 구현.
- 명시적 목록·요청 예산·간격·동시 실행 차단·검증된 cache 재개·첫 실패 중단·불변 원본·소스 증거 수집기 구현. `013`은 자료 없음으로 보존하며 오류와 구분.
- 원본 재파싱과 공시 접수번호 연결로 cutoff까지 실제 관측한 연구 입력만 제공. 미래 정정이 과거 입력을 바꾸지 않고, 미연결·미관측·모순된 버전은 사용하지 않는 테스트 통과.
- 같은 기간의 원문 금액과 관측 입력 보존까지 구현했으며, 회계 성장률·공시 매매 규칙·수익률 검증으로의 연결은 미구현. 구체적인 전략 방향은 [연구 안내](dart-research.md)의 선택지로만 기록.
- 오늘 실제 인증 요청 3회: 연결 확인, 전체 재무제표, XML 형식 비교. 모두 HTTP 302였으며 정상 snapshot은 0개. 금융 데이터가 확보됐다고 표시하지 않음.
- 키가 JSON unicode escape로 반사된 경우에도 저장을 거부하고, 임의 응답 메시지와 요청 URL을 로그로 내보내지 않는 테스트 통과.

- 9월 22일과 23일 양 시장의 종목 집합을 비교해 코스닥 신규 1종목을 발견했고, 23일 종목기본정보의 상장일과 일치. 상장 전 가짜 행을 만들지 않도록 명시적 상장·폐지 사건과 상장기간 중 연속 행 검증을 추가. 보유 종목이 행 없이 사라지면 회수 가치를 추정하지 않고 백테스트를 중단. 별도 권리·상장폐지 현금 정산 모델은 아직 없다.
- 네 일봉 원본으로 2거래일·5,525행·신규상장 사건 1건의 진단 dataset을 실제 CLI에서 생성·검증. 섹터·멤버십·거래 가능 상태와 원본 공개시각은 시점 검토 전이라 `PointInTimeCertified=false`이고 연구 성과로 사용하지 않음.

- 9월 25일과 28일의 일봉 API는 HTTP 200·0행이었다. 빈 응답만으로 휴장일 또는 결측 여부를 인증하지 않았다. [초기 품질 감사](krx-data-audit.md)에 범위와 한계를 기록.

## 2026-09-29 추가 진전

- 양 시장 32개 일별 응답을 추가 수집하여 9월 1~28일 18개 후보 거래일·36개 원본·49,747행을 감사했다. 누락/빈/형식 오류 0, 무거래 행 2,110개. 종목 출현 6건·소멸 8건·주식 수 변화 194건·35% 초과 미조정 종가 변화 54건을 찾아 `REVIEW_REQUIRED`로 기록. 이 수치는 일별 발생 건수이며 상장폐지나 기업행위가 확정된 건수가 아니다.
- 출현 6건 모두 9월 23일 기본정보의 상장일과 관측 등장일이 일치했다. 소멸 8건은 이후 [공개 KIND 상장폐지현황](https://kind.krx.co.kr/investwarn/delcompany.do?method=searchDelCompanyMain)의 회사 식별자·시장·회사명·폐지일과 대조해 폐지일/사유를 확인했다. 이는 사후 공식 현황의 확인이며 최초 공시 시각·과거 체결 가능성·잔여 권리 회수액의 증거는 아니다. 관련 ISIN이 기본정보의 다른 종목코드·시장으로 이어지는 대응은 없었다.
- 9월 28일은 29일 00:18 KST 관측에서 양 시장 0행, 23:29~23:31 관측에서 각각 942·1,821행이었다. 이전 빈 원본을 덮어쓰지 않았다. 정확한 제공시각·변경 원인은 아직 확정하지 않았으며 다음날 시가 사용 가능성을 이 사례로 인증하지 않는다.
- 공식 KRX 공개 휴장일 화면에서 2026년 17개 휴장 날짜와 9월 범위 후보 18일을 실제 CLI로 보존. 수집 날짜와 일치했다. 공개 화면 조회가 Open API 제공시각이나 결제 달력을 인증하지는 않는다.
- 최초 거래일 상장 사건의 경계 오류, AI 학습 분할에서 사건 누락, 재상장 가격을 하나의 연속 계열로 전달하던 문제를 수정. 미래 가격/사건/세금표가 익명 학습 입력을 바꾸지 않는 테스트를 추가했다.
- 명시적 거래일·결제일별 매도세 표와 모든 세션 비용 범위 검증을 추가. 실제 매도와 순청산가치에 같은 요율을 적용하고 JSON 복원 후 비용표 내용 비교를 유지한다. 법정 기본표나 Owner 정책 승인을 자동 설정하지 않았다. [비용 검토](cost-policy.md).
- 시가 손실 판정·진입 자본에도 당일 비용을 반영하여 세율 변경 시 손실 인지가 종가까지 늦어지지 않도록 수정했다. 보유 노출의 분자는 원래 가격 기준을 유지한다. 불완전한 비용표는 연구 실행과 holdout 봉인 전에 거부하므로 검증 불가능한 설정이 미래 테스트 기간을 소모하지 않는다.
- 공식 과거 정지·상장폐지·권리 자료의 접근 경로를 확인했다. KRX 정보데이터시스템의 해당 익명 요청은 `LOGOUT`이었으나 별도 공개 KIND 상장폐지현황은 인증 없이 정상 조회했다. [역사 자료 경로](historical-data-sources.md).

## 2026-09-30 비용 진단과 공식 사건 수집

- 사전 등록한 수수료·슬리피지 가산 시나리오를 단일 연구와 공유 자본 cohort에 추가했다. holdout 이전 자료만 진단기에 전달하고, 이미 선택한 전략을 고정 재실행한다. 가족별·포트폴리오별 결과와 기준 차이·중단 사건을 보존하며 합격 판정과 가설 수를 바꾸지 않는다. [비용 악화 진단](cost-sensitivity.md).
