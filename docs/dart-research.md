# OpenDART 연구 경로

목표는 공시와 재무정보로 검증 가능한 단기 전략 후보를 만드는 것이다. OpenDART 입력을 많이 모으는 것과 양의 기대값을 확인하는 것은 별개다. 가격·거래량·체결비용·실시간 관측은 별도 데이터가 필요하며, 기존 승격 기준을 유지한다.

## 구현한 범위

| 입력 | 공식 명세 | 보존 내용 |
|---|---|---|
| 공시검색 | [공시검색](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS001&apiId=2019001) | 정정 포함 목록, 접수일, 실제 관측 시각, 원본 페이지 |
| 전체 재무제표 | [전체 재무제표](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS003&apiId=2019020) | 사업연도·보고서·CFS/OFS, 계정ID·명칭·상세, 통화, 금액 원문 |
| 자사주 취득 결정 | [자사주 취득 결정](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS005&apiId=2020038) | 접수번호와 취득 계획 등 원문 필드 |
| 유상증자 결정 | [유상증자 결정](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS005&apiId=2020023) | 접수번호와 발행·자금 목적 등 원문 필드 |

`dart-collect`는 명시적인 요청 목록을 순서대로 수집한다. 회사 코드는 실험 대상 지정이며 과거 전체 상장 universe 인증이 아니다. 예시의 삼성전자 하나로 시장 전체 성과를 주장하지 않는다.

- 최대 50개 요청 목록, 실행당 1..50회 예산, 최소 1..60초 간격. 기본 예산은 3회다. 이는 공급자의 일별 허용량을 대신하는 규칙이 아니다.
- 원본과 hash를 요청마다 먼저 저장하고, 같은 계획의 중복 실행은 파일 lease로 차단한다.
- 재개할 때 기존 원본을 검증한다. 변조를 발견하면 재조회로 덮지 않는다. 정상 `013` 응답은 관측된 자료 없음이며 빈 원본도 보존한다.
- 첫 실패에서 중단한다. 요청 시도와 실패 종류·HTTP 상태를 보존하며 URL·키·오류 본문을 기록하지 않는다. 실패 요청을 자동 재시도하지 않는다.
- 같은 Label의 재개는 이미 받은 snapshot을 다시 가져오지 않는다. 새 시점의 관측은 명시적으로 새 Label을 사용한다. 새 Label이나 반복 수집은 독립적인 투자 성과가 아니다.
- 소스 archive와 실행 receipt를 함께 보존한다. 데이터 원본은 `artifacts/`에 두며 공개 Git에 넣지 않는다.

## 실행과 시점 결합

```powershell
dotnet run --project src/Investment.Cli -c Release -- dart-collect --plan config/dart-collection.example.json --max-requests 3
```

예시 계획에는 CFS 연간 재무제표, 자사주 취득, 유상증자 요청이 있다. 실제 연구 회사와 보고서·기간을 정한 계획은 `data/private/`에서 관리한다. 입력 검증과 HTTP 요청은 별개이며, 응답 없이는 데이터 확보로 표시하지 않는다.

관련 접수번호를 포함하는 공시 목록도 수집해야 한다. 재무제표 사업연도나 접수번호 앞자리에서 공개 시각을 추정하지 않는다.

```powershell
dotnet run --project src/Investment.Cli -c Release -- dart-disclosures --start 2025-08-01 --end 2025-08-31 --corp-code 00126380
dotnet run --project src/Investment.Cli -c Release -- dart-context --plan data/private/dart-context.json
```

`dart-context.json` 형식은 다음과 같다. 파일 경로는 실제 수집 결과로 교체하고 Cutoff에 명시적인 시간대를 사용한다.

```json
{
  "SnapshotFiles": ["artifacts/dart-collections/PLAN_HASH/dart-facts-QUERY_HASH.json"],
  "DisclosureFiles": ["artifacts/dart-disclosures-BATCH_ID.json"],
  "CorpCode": "00126380",
  "Cutoff": "2026-09-28T09:00:00+09:00"
}
```

결합기는 원본을 재파싱해 정규화 자료와 대조한다. 해당 cutoff까지 관측한 최신 요청 snapshot을 선택하고, 같은 회사·접수번호의 공시 목록과 연결된 행만 노출한다. 사용 시각은 `max(재무/이벤트 실제 관측시각, 공시 사용시각)`이다. 공시 사용시각에는 기존의 접수일 다음 날 기준과 실제 목록 관측 시각을 모두 적용한다. 미래 정정 자료를 추가해도 과거 cutoff의 입력은 바뀌지 않는다. 같은 시각에 모순된 원본이나 중복 fact 버전이 있으면 검토가 필요하다.

오늘 받은 과거 재무제표는 오늘 이후의 연구 입력이다. 역사적 공시 후 수익률 백테스트에서 그때 알고 있던 재무 수치로 사용하지 않는다. 연결되지 않은 접수번호는 입력에서 제외한다. 현재 기업개황을 과거 산업 분류나 종목 구성으로 사용하지 않는다.

재무 금액은 문자열로 보존한다. 결측을 0으로 바꾸거나, 다른 통화·연결/별도 기준을 섞거나, 분기 3개월 금액과 누적 금액을 섞어서 성장률을 만들지 않는다. `thstrm_amount`와 `thstrm_add_amount`의 차이와 각 보고서 코드의 의미를 검토한 다음 계정별 파생 지표를 추가한다.

## 다음 전략 연구의 선택지 — 아직 승인·구현된 매매 규칙이 아님

| 후보 | 필요한 추가 검증 | 주요 한계 |
|---|---|---|
| 공시 실적 성장과 가격 추세 결합 | 동일 계정·통화·기준의 분기 비교, 실제 공시 관측 이후 가격 반응 | 애널리스트 예상 자료가 없으면 실적 서프라이즈라고 부르지 않음 |
| 자사주 취득 공시 후 반응 | 취득 계획 규모, 시가총액·거래량, 실행 여부, 기간별 반응 | 취득 결정은 실제 매수 체결이나 수익 보장이 아님 |
| 유상증자 공시 위험 필터 | 발행 방식·희석·자금 목적과 가격 반응 | 증자만으로 일률적인 매도 규칙을 만들지 않음 |

첫 연구 방향으로는 공시 실적 성장과 기존 가격 추세의 결합을 권장한다. 회계 비교 검증은 필요하지만 기존 일봉·수일 보유 구조에 연결하기 쉽다. 세 후보 모두 원본·시점 기록, 사전 등록, 후보 전체 통계 보정, 가격 기반 walk-forward와 forward paper 검증을 거쳐야 한다. 실제 매매 조건과 임계값은 아직 선택하지 않았으며 현재 `dart-context` 결과에는 매매 신호나 수익률 판정이 없다.

## 현재 확인된 결과

2026-09-28 연결 확인, 전체 재무제표 수집 시도, 공식 XML 형식 비교에 실제 인증 요청을 총 3회 사용했다. 세 요청 모두 HTTP 302였다. 정상 공시·재무 snapshot은 0개이며 투자 목표는 미완료다. 원인을 확정하기 전 반복 호출량을 늘리지 않는다. 외부 공인 IP 조회는 별도 승인 전 실행하지 않는다.
