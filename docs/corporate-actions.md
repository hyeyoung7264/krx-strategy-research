# 기업행위 근거와 시점별 조회

분할·병합·배당은 가격, 보유 수량, 취득 원가, 미수 권리, 현금과 거래 가능 시점에 서로 다르게 영향을 준다. 현재 구현은 **공식 원문 수집과 불변 해석 기록부**까지다. 이 기록이 백테스트의 수량이나 paper 잔고를 변경하지 않으며, 기존 엔진은 기업행위가 표시된 자료를 계속 거부한다. 회계 적용 전제부터 확보하는 단계이고 실증 연구 완료가 아니다.

## 원문과 해석

`kind-notice --source URL`은 지정된 KIND 공개 공시 HTML 주소를 한 번 읽는다. 원문 응답 바이트를 Base64로 저장하고 SHA-256, 실제 관측시각, URL, 서버의 미디어 형식과 문자셋 선언을 함께 보존한다. 원문을 디코딩해 다시 인코딩한 hash가 아니다. 별도 로그인·쿠키·인증키를 사용하지 않고 리디렉션, 다른 호스트, 허용 경로 밖 URL, 과대 응답과 시간 초과를 거부한다. URL의 날짜나 HTTP 헤더를 최초 공시시각으로 추정하지 않는다.

해석 기록에는 다음을 명시한다.

- 동일 사건의 `ActionKey`, 개별 판본의 `RevisionKey`, 직전 판본의 `SupersedesRevisionKey`.
- 시장·종목코드·표준코드와 별도 상장 구간 식별자. 같은 종목코드가 다시 사용되어도 사건을 자동 합치지 않는다.
- 각 근거의 URL·원문 hash·관측시각, 해석한 필드 위치와 검토 메모.
- 해석 기록시각, 발표/확정/취소 상태, 분할 또는 현금배당 조건.

정정은 이전 기록을 덮어쓰지 않고 선행 판본을 지목하는 새 기록으로 추가한다. 사건별 단일 연결만 허용하며 누락된 선행 판본, 분기, 다른 증권으로의 변경, 시간 역전과 취소 뒤의 재활성화를 거부한다. 취소는 과거 판본을 되살리는 대신 조회 결과에 취소 상태로 남는다. 잘못된 기록을 삭제하거나 취소 사건을 새로운 사건처럼 다시 등록하는 판단까지 자동 해결하지는 않는다.

## 두 개의 시간축

조회는 시장 정보 기준시각과 기록부 기준시각을 함께 받는다. 기본 `OBSERVED` 방식에서는 해당 판본의 모든 근거를 실제 관측한 뒤에만 조건을 알 수 있다고 취급한다. 오늘 수집한 과거 공시는 과거 시장 조회에 나타나지 않는다.

`REVIEWED_PUBLICATION`은 검토된 역사적 공개시각의 근거가 있는 판본에 한해서 그 시각을 사용하는 명시적 회고 조회다. 공개시각 근거가 없으면 실제 관측시각을 사용한다. 역사적 시각을 사용했는지 결과에 표시하며, 수동 해석이나 메모만으로 자료를 시점 인증하거나 paper 적격으로 승격하지 않는다. 기록부 기준시각 이전에 기록되지 않은 해석·정정은 두 방식 모두 제외한다.

조회 결과와 그 hash에는 해당 시점에 보이는 판본만 들어간다. 전체 기록부 hash나 미래 판본 수·내용을 신호 입력에 섞지 않는다. 별도의 전체 기록부 hash는 감사용이다. 공개시각과 실제 관측시각의 순서가 판본 간 일관되지 않으면 자동으로 최종 판본을 선택하지 않고 입력을 거부한다.

현재는 시간순으로 누적되는 해석 판본을 지원하며, 기존 해석의 공개시각을 사후에 소급 수정하는 모델은 아니다. 관측 시각으로 기록한 사건을 나중에 더 이른 역사적 시각으로 보강하려는 추가는 거부한다. 과거 기록시각을 다시 쓰거나 같은 사건에 새 식별자를 붙여 우회하지 않는다. 더 오래된 공시를 뒤늦게 발견했다면 최신 확정 조건 전체를 유지한 새 관측 판본의 근거로 보강할 수 있다. 실제 공시 순서와 해석·공개시각 검토의 정정 이력을 분리하는 확장은 아직 필요하다.

역사적 공개시각 proof는 그 판본의 조건 전체에 대한 수동 검토다. 시각은 proof가 가리킨 원문을 실제 관측한 때보다 늦을 수 없다. 다른 보조 근거에 포함된 오래된 원공시의 관측시각을 정정 공시 공개시각의 상한으로 쓰지는 않는다. 근거가 여러 개라는 사실만으로 모든 조건의 최초 공개시각이 자동 증명되지는 않는다.

## 실행 형식

`corporate-append`의 `--manifest` 파일에는 `Revision`과 `SnapshotFiles`를 둔다. `Revision`은 위 식별자·시각·근거·조건을 가진 `CorporateActionRevision`이며 `SnapshotFiles`는 `kind-notice`가 저장한 로컬 JSON 경로 배열이다. 근거의 `Source`·`SourceHash`·`ObservedAt`은 원본과 정확히 일치해야 한다. `RecordedAt`은 해당 근거를 모두 관측한 이후의 실제 해석 기록시각이다. 처음에는 `--state`를 생략하고 이후에는 이전 기록부 파일을 지정한다. 각 호출은 새 hash의 파일을 게시하며 기존 파일을 덮어쓰지 않는다. 로컬 파일의 분기 저장 자체를 전역 금지하는 다중 작성자 장부는 아니다.

```powershell
dotnet run --project src/Investment.Cli --no-restore -- kind-notice --source https://kind.krx.co.kr/external/2024/11/15/000107/20241115000180/68155.htm
dotnet run --project src/Investment.Cli --no-restore -- corporate-append --manifest data/private/my-action.json
dotnet run --project src/Investment.Cli --no-restore -- corporate-at --state artifacts/corporate-ledger-HASH.json --cutoff 2024-11-20T09:00:00+09:00 --recorded-cutoff 2026-09-30T10:00:00+09:00
```

위 시각과 경로는 형식 예시다. 실제 조회 시각보다 미래인 기준시각은 허용하지 않는다. 시각 인수에는 UTC `Z` 또는 숫자 시간대가 필요하다. 역사적 공개시각 근거를 별도 검토한 회고 조회에서만 `--timing REVIEWED_PUBLICATION`을 명시한다. 반환 파일은 보이는 조건만 포함하며 원문과 전체 기록부는 별도로 로컬 보존한다. 원본·개인 경로·전체 해석 자료는 공개 저장소에 넣지 않는다.

## 실제 공식 사례가 요구하는 구분

남양유업의 [최초 분할 결정](https://kind.krx.co.kr/external/2024/09/09/000281/20240906000067/91128.htm)은 10:1 분할, 2024-11-12 효력 발생, 11-06~19 거래정지 **예정**을 담았다. 이후 [변경상장 안내](https://kind.krx.co.kr/external/2024/11/15/000107/20241115000180/68155.htm)는 11-20 변경상장·거래재개를 명시한다. 최초 예정 일정을 실제 거래정지 이력으로 확정하지 않는다. 효력일에 수량만 10배로 바꾸고 정지 중 남아 있는 옛 종가로 평가하면 가짜 평가이익이 생긴다. 총 주식 수에는 소각도 영향을 주므로 총수 변화에서 보유자의 분할 비율을 추정하지 않는다.

실제 KRX 일봉 6개 날짜를 별도로 수집해 보통주·우선주를 대조했다. 최초 예정 정지일에는 실제 거래가 있었고, 효력일과 변경상장 전날은 무거래·기존 가격 단위가 남아 있었으며 변경상장일에는 가격 단위와 상장주식 수가 바뀌었다. 이어 확보한 [10월 30일 정정 공시](https://kind.krx.co.kr/external/2024/10/30/000193/20241030000476/91128.htm)는 정지 시작일을 11-06에서 **11-08**로 변경했다. [12월 24일 결과보고서](https://kind.krx.co.kr/external/2024/12/24/000635/20241224001557/00693.htm)도 분할 경과로 11-08~19 정지, 11-12 효력, 11-20 상장을 기재한다. 최초 계획·정정 계획·사후 경과를 구분해야 한다.

원시 가격 단위 전환일의 일부 표본 확인은 모든 기업행위의 처리, 계좌 입고, 전체 정지 구간이나 최초 공개시각의 증거가 아니다. 당일 거래소의 정지 안내 원문과 정확한 역사적 공개시각은 아직 확보하지 않았다. 원본 가격 행은 로컬에만 보존한다. 실제 사례의 기록부는 원래 확정 조건을 유지하면서 늦게 찾은 정정·결과보고서 근거를 추가하고 역사적 공개시각은 비워 둔다.

분할 조건은 법적 효력일·원시 가격 단위 전환일·거래재개일을 분리하고 모르는 값은 비워 둔다. 거래소의 재개 공시가 개별 계좌에 주식이 입고되어 즉시 매도 가능하다는 증거는 아니다. 단주 처리는 별도 근거가 필요하며 일괄 반올림이나 당시 시세를 임의로 적용하지 않는다.

현금배당 조건도 주당 세전 금액·배당락일·기준일·예정 지급일을 나눈다. 미수배당은 지출 가능한 현금이 아니고, 매도 후에도 남을 수 있다. 실제 입금액·세금·입금시각이 없는 상태에서 지급일 시가에 현금을 늘리지 않는다. 아직 확인되지 않은 항목을 이전 날짜나 0으로 채우지 않는다.

## 이어질 회계 구현

원시 가격·원래 체결은 보존한 채 판단 시점에 알려진 조건으로 신호용 비교 가격을 구성해야 한다. 보유 lot의 현재 수량·잔여 취득 원가·stop 기준, 정지 중 평가 단위, 부분체결 거래량 단위와 거래 가능 재고를 함께 처리해야 한다. 배당은 권리 발생과 실제 현금 정산을 별도 사건으로 기록해야 한다.

백테스트와 paper는 같은 권리 계산을 사용하고, paper 장부는 사건을 정확히 한 번만 적용하며 재생에서 검증해야 한다. 정상 권리 반영은 현재 위험 중단용 `Events`와 분리한다. 미래 정정·최종 지급액·분할 후 가격을 이전 판단에 사용하지 않는 테스트와 학습/검증/holdout 분할 처리도 필요하다. 이 회계, 실제 시점 증거, 전체 사건의 완전성 검토가 남아 있다.
