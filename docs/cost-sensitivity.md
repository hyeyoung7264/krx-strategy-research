# 비용 악화 진단

한 비용 가정에서만 수익이 나는 전략을 식별하기 위해, 연구 시작 전에 소수의 수수료·슬리피지 가산 시나리오를 등록한다. 단일 전략군과 공유 자본 포트폴리오 모두 같은 방식으로 검사한다. 실제 수수료나 호가 자료를 확보했다는 뜻은 아니다.

`ResearchPlan.CostStress`는 선택 사항이다. `config/research-cost-stress.example.json`은 기본 연구 설정에 두 가지 가상 시나리오를 추가한 예다. `CommissionAdd`와 `SlippageAdd`는 비율의 가산값이며, 수수료는 기존 엔진과 같이 매수·매도 각각에 적용한다. `0.001`은 0.1%포인트다. 매도세와 결제일 표, 위험 한도, 초기 자본, 거래 기간은 바꾸지 않는다. 기본 비용에 가산한 결과가 유효하지 않거나 날짜별 비용표가 부족하면 연구 전에 중단한다.

시나리오는 holdout 예약의 연구 계획과 아카이브에 함께 기록된다. 과거 연구 결과를 본 뒤 같은 봉인 기간에 시나리오를 추가하여 새 연구로 실행하는 명령은 제공하지 않는다. 예시의 `PolicyReviewed=false`는 그대로 유지한다.

## 계산 범위

- 기존 walk-forward의 각 미래 테스트와 최종 validation에서 선택된 전략을 고정한다. 비용이 바뀌었다는 이유로 후보를 다시 선택하지 않는다.
- 진단 실행기는 holdout 시작 전으로 잘라낸 데이터만 받는다. 가격·세션·상장 사건에서 holdout을 제외하고, 학습 이전 관측을 포함한 앞선 가격 이력은 신호 계산에 사용한다.
- 비용이 주문 크기·현금·손실 중단·체결에 미치는 영향을 보도록 백테스트를 다시 실행한다. 이전 체결 결과에서 비용만 빼는 방식은 아니다.
- 기간별 수익률·MDD·거래 수·회전율·미청산 포지션·중단 사건과 기준 실행 대비 차이를 기록한다. 겹치는 기간의 일수나 거래를 합쳐 독립 표본 수를 늘리지 않는다.

비용이 커지면 매매가 줄거나 위험 중단이 빨라져 특정 표본의 수익률이 오히려 높아질 수도 있다. 이를 개선된 전략으로 선택하거나 수익이 반드시 감소해야 한다는 검사를 두지 않는다. 현행 합격 판정, 후보 수 보정, paper 시작 조건은 진단 결과로 바꾸지 않는다. 시나리오별 신뢰구간이나 양의 기대값 합격 판정도 제공하지 않는다.

## 실행과 재현

```powershell
dotnet run --project src/Investment.Cli -c Release --no-restore -- cohort-demo --config config/research-cost-stress.example.json
dotnet run --project src/Investment.Cli -c Release --no-restore -- reproduce --archive artifacts/archive-<id>.json
```

첫 명령의 자료는 합성 데이터다. 계산과 재현을 검증할 뿐 실제 시장 성과가 아니다. 아카이브의 설정·선택 전략·진단 값은 재현 시 비교하고, 재현 결과는 새로운 독립 증거로 세지 않는다. 실제 자료를 쓰는 연구는 기존 데이터 검토와 holdout 봉인 절차를 그대로 따른다.
