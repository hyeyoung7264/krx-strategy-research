# 분할·병합의 수량과 가격 단위 회계

백테스트와 paper 장부는 명시적인 주식 단위 변경을 같은 계산으로 처리한다. 원시 일봉과 최초 체결은 보존하며 경제적 보유 수량·현재 손절 기준·평가 가격·과거 거래량의 단위를 함께 맞춘다. 현금배당·단주 현금 정산·합병·상장폐지 회수는 별도 모델이 필요하다. 이 구현이 실제 자료의 시점 인증이나 수익성 검증을 뜻하지 않는다.

## 필요한 입력

Dataset과 KRX manifest의 선택적 `ShareUnitChanges` 항목은 다음 값을 가진다. 실제 자료에서는 원공시·정정·종목 동일성·실행 일정·당시 공개시각을 검토해 근거를 연결해야 한다.

| 필드 | 의미 |
|---|---|
| `ActionKey`, `Ticker` | 동일 사건의 고유 식별자와 적용 증권의 종목코드 |
| `EffectiveDate` | 해당 날짜의 모델상 개장 전 보유 권리를 새 주식 단위로 변환 |
| `PriceUnitDate` | 공급원 원시 가격이 새 주식 단위로 바뀌는 날짜 |
| `NewShares`, `OldShares` | 보유 수량의 정확한 정수 비율 |
| `AvailableAt`, `Evidence` | 효력 발생을 처리하기 전에 알려진 조건과 검토 근거 |

가격 단위 전환은 효력일보다 이를 수 없고, 조건은 효력일 개장까지 알려져 있어야 한다. 개장과 입고 검사는 [날짜별 정규장 시간](session-hours.md)을 사용한다. 현재 인증 dataset은 실제 거래일 효력만 지원하며 휴장일의 경제적 효력시각은 추정하지 않는다. 두 날짜 사이의 거래 가능 행은 거부한다. 중복 식별자·같은 증권의 같은 날 다중 변경·관련 증권 누락·변환 도중 상장 구간 변경도 거부한다. `CorporateAction=true` 표시는 대응하는 명시적 사건이 있어야 한다. 이 표시는 다른 권리 종류의 해결을 인증하지 않는다.

`ShareInventoryCredits`는 변환된 가상 보유분 전체를 매도 가능한 수량으로 취급할 수 있다는 별도 모델 입력이다. `ActionKey`, `CreditedAt`, `AvailableAt`, `Evidence`를 기록한다. 실제 입고 시점보다 먼저 알고 있었던 것으로 기록할 수 없고, 사용 시 두 시각 모두 판단 시점 이하여야 한다. 거래소 재개일만으로 이 입력을 자동 만들지 않는다. 실제 계좌에 존재하지 않는 paper 보유분에 실제 계좌 잔고 수량을 그대로 복사하는 기능도 아니다. 공급원/계좌 처리 규칙과 가상 거래 모형의 적용 근거를 검토해야 하며, 파일 입력은 여전히 시세나 입고를 인증하지 못한다.

공시 해석 기록부에서 회계 입력으로 자동 승격하지 않는다. [기업행위 기록부](corporate-actions.md)는 원문·해석·정정 근거를 보존하고, 이 회계 입력은 별도의 검토된 실행 조건을 요구한다. 현재 확보한 남양유업 원문만으로 정확한 역사적 공개시각이나 계좌 입고를 채우지 않는다.

## 보유분과 평가

효력이 발생하면 기존 보유 lot의 수량에 비율을 적용하고 손절 기준은 역비율로 바꾼다. 손절 기준은 최초 값을 보존한 채 적용된 누적 비율에서 다시 계산해 연속 분할·병합의 중간 반올림이 위험 경계를 바꾸지 않도록 한다. 총 잔여 취득원가·현금·최초 진입가격·최초 수량은 바꾸지 않는다. 변환 결과가 단주이거나 지원 정수 범위를 넘으면 계산을 중단하며 버림·반올림·가상의 현금 보상을 하지 않는다.

예를 들어 10주를 100원에 보유하고 10:1 분할이 발생하면 경제 수량은 100주, 총 취득원가는 1,000원이다. 공급원이 아직 구 단위 100원을 제공한다면 10원으로 환산해 평가한다. 공급원이 새 단위 10원을 제공하기 시작하면 그대로 평가한다. 이 과정에서 수익·현금·회전율·세금은 발생하지 않는다. 시가가 없을 때 쓰는 과거 종가도 그 종가가 나온 날짜의 단위로 환산한다.

원가 배분은 부분 매도 시에만 현재 수량 비율로 한다. 매도 수량은 해당 매도 날짜의 단위이며 `OriginalEntryQuantity`, `EntryPrice`, `AllocatedCost`, `ShareUnitActionKeys`와 별도 변환 기록으로 원래 체결 및 적용 경로를 남긴다. 기존 가공 상태에서 최초 수량을 알 수 없다면 값을 만들어 채우지 않는다. 거래 통계는 분할 전후 매도 주식 수를 더하지 않고 완료된 포지션의 손익과 보유기간을 집계한다.

입고 근거가 없는 기존 lot은 계속 경제적 가치에 포함하지만 매도하지 못한다. 새 단위로 정상 매수한 별도 lot에는 과거 보유자의 입고 제한을 붙이지 않는다. 같은 증권·전략의 중복 보유 제한과 포트폴리오 위험 한도는 유지한다. 일봉 백테스트는 장중 저가가 입고 전인지 후인지 알 수 없으므로 개장까지 가용성을 확인한 보유분에만 해당 날 청산을 허용한다. Paper는 실제 관측 순서에서 가용성을 확인한 뒤 기존 청산 규칙을 적용한다.

## 신호·유동성·검증 구간

신호와 시장 상태는 그 판단 시점에 알려진 조건만 사용해 비교용 종가를 같은 경제 단위로 맞춘다. `Signal.Price`는 원래 관측 가격을 보존하고 근거 hash에는 원시 이력과 실제 환산에 쓰인 사건을 묶는다. 원시 OHLCV를 수정주가로 덮어쓰지 않는다.

과거 거래량도 현재 경제 단위로 변환한다. 병합 후 비교 거래량은 소수일 수 있으므로 decimal 값으로 유지하고 참여율을 적용한 최종 주문 한도에서만 내림한다. 실제 거래는 원시 가격 단위 전환 뒤에만 가능해 그때의 경제 단위와 체결 단위가 일치한다.

AI 학습 자료와 비용 진단에서는 구간 안에 효력이 있고 해당 기준시각까지 알려진 사건만 남긴다. 다음 검증 또는 holdout 개장 직전까지 공개되지 않은 자료를 미리 사용하지 않는다. 필요한 과거 사건과 이미 알려진 미래 전환 일정은 유지하되 이후 입고 관측·미래 사건·그 근거를 입력 hash나 익명 프롬프트에 섞지 않는다. AI는 가격·decimal 거래량을 같은 단위로 정규화하며 종목명·사건 식별자·실제 날짜·공시 메모는 프롬프트로 보내지 않는다.

## Paper 재생과 남은 범위

Paper 관측에 사건과 입고 근거를 넣으면 원래 관측과 상태에 보존한다. 기존 보유 lot별 적용 식별자로 중복 변환을 막고 최초 위험 평가 전에 수량을 반영한다. 이미 처리했어야 할 사건을 나중에 받아 과거 잔고를 다시 쓰는 방식은 거부한다. 정상 변환 감사는 위험 중단 사건과 구분한다. 장부 재생은 저장된 관측만으로 변환·잔고·원가·감사 기록을 다시 계산하고, 시작 상태에 이익이나 변환 기록을 미리 넣는 것을 거부한다.

미확인 정정, 단주 권리, 현금배당 미수금/정산, 유상증자·합병·폐지 권리, 장중 단위 변경과 부분 입고는 아직 지원하지 않는다. 정확한 과거 공급원 가격 단위와 입고 모델 근거도 추가로 확보해야 한다. 수동 입고/시세 자료를 사용한 실행은 실제 forward paper 성과로 승격되지 않는다.
