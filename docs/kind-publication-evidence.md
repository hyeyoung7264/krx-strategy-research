# KIND 목록 시각과 원문 연결

공시를 나중에 수집했을 때 효력일을 최초 공개시각으로 사용하면 미래 정보가 섞일 수 있다. `kind-publication`은 공개 목록의 표시 시각을 보존하고 해당 행이 어떤 원문으로 연결되는지 대조하는 별도 수집기다. 현재 화면을 수집한 증거이며 역사적 공개시각 인증은 아니다.

## 사용 범위

```powershell
dotnet run --project src/Investment.Cli --configuration Release --no-restore -- kind-publication --ticker 145210 --start 2025-03-21 --end 2025-03-21 --acceptance-no 20250321000060
```

명시한 종목코드와 날짜 범위로 목록 한 페이지를 요청한다. 전체 건수와 실제 행 수가 일치하는 1/1페이지, 최대 100행만 허용한다. 0행·다중페이지·목표 접수번호 누락·중복이나 예상하지 않은 구조는 성공으로 처리하지 않는다. 더 좁은 범위는 새 요청으로 명시해야 하며 자동 반복 조회는 하지 않는다.

목록, 뷰어, 본문 경로 안내의 순서로 최대 세 번 요청한다. 요청 사이에 최소 1초 간격을 두며 로그인 쿠키·인증키·리디렉션·JavaScript 실행을 사용하지 않는다. 반환된 외부 링크를 임의로 따라가지 않는다. 실제 공시 HTML 본문이 필요하면 별도 `kind-notice` 명령으로 그 URL을 수집한다.

## 식별과 시간의 의미

- 목록의 접수번호, 뷰어의 접수번호, 선택된 본문 문서번호, 서버가 반환한 공식 원문 URL을 구분해서 검증한다. 접수번호와 문서번호가 같다고 가정하지 않는다.
- 요청에 넣은 코드를 응답 코드로 간주하지 않는다. 뷰어에 실제 표시된 대표 종목코드를 대조한다. 목록의 회사 ID는 별도 식별자이며 끝에 숫자를 붙여 종목코드로 바꾸지 않는다.
- 목록과 뷰어의 제목은 서로 다를 수 있으므로 연결의 일치 키로 삼지 않는다. 대표 종목코드 하나가 보통주·우선주 등 공시의 모든 적용 증권을 뜻하지 않는다. ISIN·적용 범위는 본문과 기본정보를 추가 대조해야 한다.
- 표시 날짜와 `HH:mm` 문자열을 분 단위 정밀도로 보존하고 시간대는 `null`로 둔다. 초, UTC 시각, `AvailableAt`이나 최초 공개 보장을 만들어 넣지 않는다. 실제 수집시각 `ObservedAt`은 별도로 남긴다.

2026-09-30 사전 조사에서 [공식 공시검색](https://kind.krx.co.kr/disclosure/details.do?method=searchDetailsMain)의 두 실제 사례를 확인했다. 다이나믹디자인의 접수번호 `20250321000060`은 문서번호 `20250321000242`와 [정지 공시](https://kind.krx.co.kr/external/2025/03/21/000060/20250321000242/99810.htm)로, 남양유업의 `20241115000107`은 `20241115000180`과 [변경상장 공시](https://kind.krx.co.kr/external/2024/11/15/000107/20241115000180/68155.htm)로 연결됐다. 목록의 표시 시각은 각각 2025-03-21 08:58과 2024-11-15 17:35였다. 화면 시각의 시간대·최초 공개 의미·당시 판본 불변성은 이 연결 검사로 입증되지 않는다.

## 보존과 실패

CLI는 요청 전에 실행 소스와 시도 기록을 저장한다. 완전한 응답을 받을 때마다 요청 방법·URL·본문, HTTP 상태·Content-Type·Content-Encoding, 실제 관측시각, 응답 바이트와 SHA-256을 저장한다. HTML 해석에 실패해도 앞 단계의 원본을 버리지 않는다. 응답 크기 제한이나 중간 연결 실패로 완전한 본문을 받지 못했다면 부분 바이트를 완전한 원본으로 저장하지 않는다.

단계별 보존에 실패하면 다음 요청을 중단한다. 최종 기록의 `CaptureFiles`는 실제 저장에 성공한 파일만 가리킨다. 성공 상태도 `COLLECTED_UNREVIEWED`이며, 수집 실패·응답 거부·저장 실패를 구분한다. Core 수집기는 전달받은 취소 토큰도 처리하지만 현재 CLI의 Ctrl+C나 프로세스 강제 종료에는 연결하지 않았다. 이 경우 기존 소스·시도·단계별 원본만 남고 최종 기록은 없을 수 있다. 오류 종류만 기록하고 공급원의 예외 메시지를 결과에 복사하지 않는다.

최종 기록도 원본에서 재파싱해 검증한다. 시스템 시계 역행처럼 기록 자체가 검증에 실패하는 경우에는 시각을 고치지 않고 `ReceiptValidation=REJECTED`로 실패 자료를 보존한다. CLI는 검토 필요 상태와 실패 종료코드를 반환하며 검증에 실패한 공개시각 해석을 출력하지 않는다.

공개 화면의 구조가 바뀌면 자동 추측 대신 검토가 필요하다. 지원되는 공식 Open API라는 보장은 없다. 이 증거를 기존 기업행위 기록부의 `REVIEWED_PUBLICATION`이나 dataset 시점 인증으로 자동 승격하지 않는다. 시간대·필드 의미, 정정 이력, 해당 판본의 조건, 적용 증권과 권리·정산을 추가 검토해야 한다.

## 실행하여 확인한 범위

2026-09-30 신규 75개 합성 사례가 통과했다. 앞서 보존한 위 두 실제 사례의 6개 응답을 추가 요청 없이 재파싱했고, 실제 CLI에서도 각 세 번씩 총 여섯 번 조회하여 두 연결을 다시 확인했다. 단계별 원본 파일과 최종 기록의 바이트 hash, 실행 소스·시도 기록이 일치했다. 현재의 공식 화면 연결을 검증한 결과이며 역사적 최초 공개시각·적용 증권 전체나 투자 성과를 인증한 결과는 아니다.
